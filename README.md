# Solaris Launcher

Современный WPF-лаунчер Solaris для Minecraft.

## Что уже есть

- Локальная регистрация и вход.
- Пароль хранится как PBKDF2-SHA256 hash + случайная salt.
- Профиль игрока и ник из логина.
- Minecraft 1.20.1 + Forge 47.4.20 для модового режима.
- Minecraft Vanilla 26.2 в отдельной папке.
- Автоматическая установка Minecraft, библиотек и Java через CmlLib.
- Автоподключение Vanilla 26.2 к `solarisplay.millida.host:25565`.
- Автоматическое обновление клиентской модовой сборки через `SolarisClient.zip` из GitHub Releases.
- Настройка RAM: 2048–4096 MB.

## Режимы

- **SOLARIS MODDED** — Minecraft 1.20.1 + Forge 47.4.20.
- **SOLARIS VANILLA** — Minecraft 26.2 + автоматическое подключение к Solaris Vanilla серверу.

## Важно

Локальная регистрация аккаунта пока работает только на конкретном ПК и не является серверной авторизацией.

Серверные файлы, мир и серверная конфигурация хранятся на хостинге Millida и не входят в репозиторий лаунчера.

## Сборка

Требуется .NET 8 SDK.

```powershell
dotnet clean
Remove-Item -Recurse -Force .\bin, .\obj -ErrorAction SilentlyContinue
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
```

Готовый EXE:

`bin\Release\net8.0-windows\win-x64\publish\SolarisLauncher.exe`

## Solaris Neon 2.2.9: более сильное размытие карточек

**Vanilla и Modded:** в обычном состоянии оригинальные фоны заметно сильнее размыты (уменьшенная до 360 пикселей по ширине копия, два прохода box blur радиуса 7). При наведении курсора оригинальная чёткая иллюстрация проявляется плавно за 185 мс; при уходе возвращается размытие за 235 мс. Фоны созданы однократно при загрузке: GPU не рассчитывает размытие на каждом кадре.

**Никаких изменений** в двух утверждённых PNG, логотипе, системе установки, сохранённых мирах или аккаунтах. Автообновление работает из версии 2.2.8 по каналу `neon-v2.2.9`.

## Solaris Neon 2.2.8: индивидуальные арты Vanilla и Modded

Отдельные оригинальные иллюстрации для карточек встроены в EXE и не зависят от старых импортированных ZIP: Vanilla — закатный мир; Modded — Create, поезд и Wither Storm.

## Solaris Neon 2.2.7: одно оформление у всех игроков

**Встроенные оригинальные арты:** `SolarisWorld.webp` (золотое кольцо, парящие острова, фиолетовый закат и Стив слева) и `SolarisModded.webp` (светящийся фиолетовый портал) закоммичены в репозиторий как сжатые качественные оригиналы.

CI обязательно сверяет SHA256 обоих изображений и конвертирует их в PNG до `dotnet restore/build/publish`. PNG компилируются непосредственно в WPF-ресурсы EXE (`pack://application:,,,/Assets/...`).

**Из коробки и офлайн:** каждый новый игрок получает одинаковые фоны входа, главного меню, Vanilla и Modded. Искать, скачивать или вручную импортировать `Solaris-Neon-UI.zip` больше не требуется.

**Совместимость:** импорт пользовательского ZIP сохраняется как дополнительная настройка и переопределяет встроенные фоны. Для исходного `Solaris-Neon-UI.zip` исправлено распределение изображений по экранам, чтобы оно совпадало с комплектной темой.

Автоустановка и обновления версии 2.2.6 не меняются: следующий релиз применяется на постоянный EXE с сохранением `%APPDATA%\\Solaris`, локального аккаунта, сохранённых настроек и Minecraft. Не меняются быстрые анимации карточек, официальная солнечная иконка и существующие игровые режимы.

## Solaris Neon 2.2.6: установка и обновления без кнопки

Начиная с **2.2.6**, скачанный `SolarisLauncher.exe` автоматически устанавливает себя при **первом обычном запуске** (без отдельной кнопки, без администратора):

1. Определяет постоянную папку `%LOCALAPPDATA%\\Programs\\Solaris Launcher`.
2. Если Solaris ещё не установлен — копирует EXE туда. Если установлен более старый EXE — обновляет его, сохранив `.previous` как резервную копию. Если установлен более новый EXE — **не перезаписывает его старым файлом**.
3. Создаёт ярлыки `Solaris Launcher.lnk` на рабочем столе и в меню «Пуск». Оба ярлыка указывают на один постоянный EXE с официальной солнечной иконкой.
4. Перезапускает Solaris из постоянной папки и закрывает первоначальную копию. При последующих запусках из постоянного расположения повторного копирования нет.
5. Как и в 2.2.5, проверяет опубликованные выпуски `neon-vX.Y.Z` и **предлагает** обновление. После согласия сверяет SHA256 и заменяет EXE на месте.

**Переход с 2.2.5:** установленный Solaris 2.2.5 при запуске сам предложит обновиться до опубликованной версии 2.2.6. Если используется скачанный EXE 2.2.6, он также сам установится (или обновит имеющуюся более старую установку).

**Устойчивость к сбоям:** если Windows запрещает копирование или создание установленной копии, Solaris сообщает об этом и продолжает работу из исходного файла. Если недоступен только рабочий стол для создания ярлыка, приложение всё равно запускается; ошибку создания ярлыка можно найти в `%LOCALAPPDATA%\\Solaris\\logs\\installation.log`. Если уже открыт установленный Solaris, закрой его перед ручным запуском скачанного более нового EXE.

**Данные отдельно:** аккаунт, пользовательская тема и Minecraft остаются в `%APPDATA%\\Solaris`, вне папки приложения. Автоматическая установка и обновления их не удаляют.

### Расположение файлов

- Постоянный EXE: `%LOCALAPPDATA%\\Programs\\Solaris Launcher\\SolarisLauncher.exe`.
- Резервная копия EXE: `%LOCALAPPDATA%\\Programs\\Solaris Launcher\\SolarisLauncher.exe.previous`.
- Minecraft, аккаунт и тема: `%APPDATA%\\Solaris`.
- Скачиваемые обновления: `%LOCALAPPDATA%\\Solaris\\updates`.

## Solaris Neon 2.2.5: предыдущий способ установки

1. Скачай официальный `SolarisLauncher.exe` из Neon GitHub Release и запусти его.
2. На экране входа нажми **«Установить Solaris на ПК (один раз)»**.
3. Solaris копирует себя в `%LOCALAPPDATA%\\Programs\\Solaris Launcher\\SolarisLauncher.exe`, создаёт `Solaris Launcher.lnk` на рабочем столе и в меню «Пуск», затем запускает установленную копию.
4. С этого момента запускай Solaris **через созданный ярлык**: его путь не меняется между версиями, как и иконка в свойствах ярлыка.
5. При следующем запуске лаунчер сам проверит выпуски `neon-vX.Y.Z` в GitHub Releases. Если новая версия опубликована, Solaris **спросит разрешение**, скачает EXE, сверит его SHA256 с `SHA256SUMS.txt` и после перезапуска заменит старый EXE на том же месте.

Предыдущий EXE остаётся рядом в файле `SolarisLauncher.exe.previous` для восстановления. Если обновление не скачалось или не прошло проверку, прежняя версия остаётся работоспособной. Для обновления нужен доступ к GitHub; без сети лаунчер продолжит открываться.

**Данные не переустанавливаются:** аккаунт, локальные настройки, тема и скачанный Minecraft находятся в `%APPDATA%\\Solaris`, отдельно от EXE. Загруженный пользователем ZIP оформления сохраняется и не перезаписывается при обновлении. Стили XAML, встроенный логотип/иконка и новые функции обновляются вместе с EXE.

### Каналы

- **Neon**: GitHub Releases с тегами `neon-v2.2.5`, `neon-v2.2.6` и т. д. Именно этот канал проверяет установленный Neon 2.2.5+.
- **Legacy stable 2.1.2**: отдельный `update.json` в ветке `solaris-2.1-polish`, без изменений.

### Выпуск следующего обновления

1. Закончи разработку в `solaris-2.2-dev`.
2. Обнови версию в `SolarisLauncher.csproj` (Version, FileVersion, AssemblyVersion), `MainWindow.xaml.cs` (LauncherVersion) и метку в `MainWindow.xaml`.
3. Дождись успешной тестовой сборки GitHub Actions.
4. Сделай финальный коммит в ветку с сообщением, начинающимся на `release:` (например, `release: Solaris Neon 2.2.6`).
5. Release workflow опубликует `neon-v2.2.6` и три постоянных файла: `SolarisLauncher.exe`, ZIP и `SHA256SUMS.txt`. Опубликованную версию нельзя перезаписывать под тем же номером — для изменений повышай версию.

**Замечание:** сейчас EXE не подписан сертификатом издателя, поэтому Windows SmartScreen может показывать предупреждение. Контрольная сумма подтверждает целостность скачанного файла по сравнению с релизом, но не заменяет цифровую подпись.
