# SOLARIS ID — отдельная серверная основа (пока НЕ развёрнута)

**Что есть:** начальный независимый ASP.NET Core 8 API с ASP.NET Identity, PostgreSQL,
регистрацией с никнеймом, подтверждением email, встроенными Identity endpoints для
входа/2FA/обновления токена/восстановления и идемпотентной загрузкой игровых сеансов.

**Чего пока нет:** подключённого Windows-лаунчера, облачного сохранения скинов,
миграции старых локальных аккаунтов, интерфейса SOLARIS CONTROL и его админских
операций, готовых миграций EF и проверенного VPS. **Не использовать в production**.

## Развёртывание через Millida VDS
Проверена возможность аренды отдельного VDS с root-доступом и установки PostgreSQL
на нём. Minecraft-сервер остаётся на отдельном игровом хостинге Millida.
Не хранить root, почту, БД или TLS-ключи в этом репозитории.

Обязательные переменные окружения (задаются только на сервере):
- `SOLARIS_ID_CONNECTION_STRING` — PostgreSQL DSN с отдельным пользователем API.
- `SOLARIS_ID_PUBLIC_ORIGIN` — HTTPS-адрес авторизации, например `https://auth.example.invalid`.
- `SOLARIS_SMTP_HOST`, `SOLARIS_SMTP_PORT`, `SOLARIS_SMTP_FROM`,
  `SOLARIS_SMTP_USER`, `SOLARIS_SMTP_PASSWORD` — рабочая почта подтверждений.

Прежде чем запускать API, требуется создать **проверенную EF миграцию** и применить
её к пустой тестовой БД. Не выполнять `EnsureCreated` вместо миграций в production.
Перед публикацией нужны:
1. Проверка права на уникальный ник, безопасной регистрации/подтверждения email,
   запрета обхода через стандартный Identity `/register`, блокировок перебора.
2. Нагрузочные и конкурентные тесты `/me/playtime`; сериализация повторных
   запросов и ограничение доверия к клиентским игровым часам.
3. Отказоустойчивые SMTP + reset, аудит, восстановление БД и резервные копии.
4. Принудительное завершение сессий забаненных пользователей и админский
   интерфейс **с обязательной 2FA**, безопасной выдачей роли вне публичных API.
5. Защищённое клиентское хранение токенов в Windows, подтверждённая миграция
   старых аккаунтов и ограниченный офлайн-режим.
6. HTTPS, reverse proxy с проверенными forwarded headers и мониторинг.

GitHub CI проверяет компиляцию **без запуска и без учётных данных**.
