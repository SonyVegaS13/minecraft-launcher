# SOLARIS NEON 2.2.10 — ПРИЁМКА И ТЕСТЫ

Статус: инструкция для проверки, а НЕ подтверждение успешного прохождения.
Рабочая версия: Solaris Neon 2.2.9. Проверяем DEV 2.2.10 отдельно.
Для каждого пункта записать: PASS / FAIL / НЕ ПРОВЕРЕНО.

## 0. Безопасный DEV-запуск
- [ ] Скопировать на отдельный диск резервную копию %APPDATA%\Solaris.
- [ ] Скачать EXE только из успешного GitHub Actions Artifacts ветки solaris-2.2-dev, НЕ из Releases.
- [ ] Распаковать DEV ZIP отдельно от рабочего установщика.
- [ ] Открыть PowerShell в тестовой папке: & '.\SolarisLauncher.exe' --dev-test
- [ ] Проверить, что DEV пишет в %APPDATA%\Solaris-Neon-Dev, НЕ в %APPDATA%\Solaris.
- [ ] Проверить, что EXE и ярлыки 2.2.9 остались без изменений.
- [ ] Вторая копия DEV не создаёт второе рабочее окно.
- [ ] Не запускать DEV EXE обычным двойным кликом! Без --dev-test он может предложить заменить рабочую 2.2.9.

## 1. Локальный аккаунт и солнышко-глаз (пункты 4, 8)
- [ ] Зарегистрировать тестовый ник и пароль; при несовпадении двух паролей регистрация запрещена.
- [ ] При входе пароль скрыт; жёлтый логотип-глаз по нажатию открывается/закрывается плавно.
- [ ] При регистрации оба поля пароля переключаются независимо, символы не теряются.
- [ ] После перехода со входа на регистрацию пароль автоматически скрывается.
- [ ] Caps Lock показывает предупреждение и убирает его при отключении.
- [ ] Неверный пароль не открывает профиль; верный открывает.
- [ ] «Запомнить меня» работает после закрытия/перезапуска; выход выполняется корректно.
- [ ] В логах нет введённого пароля или содержимого полей.

## 2. RAM (пункт 3)
- [ ] ⚙ Настройки открываются внутри одного окна, без лишнего Windows-диалога.
- [ ] Vanilla и Modded используют разные ползунки; их значения не смешиваются.
- [ ] Выбранные значения сохраняются после закрытия DEV и повторного запуска.
- [ ] На машине с 8/16/32 ГБ пределы динамические, есть запас для Windows.
- [ ] При запуске сверить параметр -Xmx в запущенном java.exe выбранного режима.

## 3. Первая и повторная установка (пункты 1, 2)
- [ ] Первая Vanilla: проверка Minecraft 26.2 и Java 25; показывается, что нужно скачать.
- [ ] Java 25 скачивается самостоятельно, проверяется SHA-256 и версия java -version.
- [ ] Первый Modded: проверка Minecraft 1.20.1, Forge 47.4.20, Java 17, модов.
- [ ] Java 17 скачивается самостоятельно; ни одна карточка не запускается на чужой версии Java.
- [ ] Следующий запуск обеих карточек: корректные файлы не загружаются заново.
- [ ] Если отсутствует один управляемый мод, он восстанавливается; пользовательские миры, saves, options.txt, config не стираются.
- [ ] При отмене или пропадании сети следующий запуск может восстановить недостающие компоненты.
- [ ] Сверить версию Vanilla 26.2 с реальным Minecraft сервером; успешная WPF-сборка не доказывает игровой вход.
- [ ] Проверить достаточно свободного места и не остаются гигантские временные ZIP после установки.

## 4. SOLARIS IGNITION (пункты 2, 10)
- [ ] Одна панель прогресса без двойных статусов и лишних окон.
- [ ] Для файлов с известным размером указанный процент — реальный процент переданных байтов текущего скачивания.
- [ ] Если длина скачивания неизвестна, показывается состояние этапа, а не выдуманный процент.
- [ ] Жёлто-оранжевая плазма, искры, движущийся светящийся край, короткая вспышка на 100%.
- [ ] Наведение на карточки Vanilla и Modded сохраняет размытую/чёткую панораму, не тормозит ввод пароля.
- [ ] После отмены/ошибки панель не зависает в ложном состоянии «Готово».

## 5. Реальное время игры и SOLARIS ACTIVITY (пункты 5, 6)
- [ ] Vanilla: зайти в одиночный мир на 2–3 минуты и выйти; часы прибавились только Vanilla.
- [ ] Vanilla: повторить с multiplayer; учёт работает не только для сервера Solaris.
- [ ] Modded: проверить одиночный и multiplayer, часы прибавляются только Modded.
- [ ] Пока Minecraft запущен, Solaris скрывается; после выхода появляется снова.
- [ ] После перезапуска остаются последнее игровое время, последний режим, дата запуска и сумма.
- [ ] Отключить сеть во время игры: локальная статистика не теряется.
- [ ] В главном окне вместо достижений отображается SOLARIS ACTIVITY.
- [ ] Нет фиктивного LEVEL 1 / игр 0, если эти показатели не отслеживаются.

## 6. Профиль и скины (пункт 4)
- [ ] Нажать на аватар, проверить открытие SOLARIS PLAYER PROFILE в том же окне.
- [ ] Имя, тип аккаунта, Vanilla/Modded/итого отражают действительные данные.
- [ ] Старым аккаунтам не подставляется выдуманная дата регистрации.

- [ ] 3D показывает лицо, спину, руки и ноги с правильными текстурами.

## 7. Облачный SOLARIS ID (пункт 7)
ВНИМАНИЕ: до установки PostgreSQL, HTTPS, SMTP и API на отдельном Millida VDS

& '.\SolarisLauncher.exe' --dev-test

- [ ] Без адреса облачного API Solaris честно сообщает «пока недоступно»; локальный аккаунт работает.
- [ ] На тестовом API регистрация email/ника и подтверждение письмом реально работают.
- [ ] Вход до подтверждения запрещён, неверный пароль не принимается, есть rate limit.
- [ ] Восстановление пароля по email-коду работает в том же окне.
- [ ] Токены хранятся в файле, защищённом Windows DPAPI; выход стирает сохранённую сессию.
- [ ] На другом ПК вход в тот же ID даёт тот же ник, часы и скин.
- [ ] При отсутствии сети данные сеансов ставятся в очередь; после подключения отправляются.
- [ ] Один и тот же ID игрового сеанса не удваивает статистику после нескольких отправок.
- [ ] Перенос из локального аккаунта требует старый пароль, подтверждение игрока; переносит часы и доступный PNG, не удаляя старый профиль.
- [ ] Повторный перенос НЕ прибавляет часы второй раз.
- [ ] Бан/отзыв сессии запрещает доступ к защищённым ресурсам.
- [ ] Сверить офлайн-состояние: нельзя выдавать его за online login с работающей авторизацией.
- [ ] Кастомный Solaris ID не подтверждает владение официальной Minecraft-лицензией; проверять совместимость с online-mode серверами отдельно.
