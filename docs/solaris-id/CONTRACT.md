# Solaris ID implementation contract

Feature branch: feature/solaris-id, base efb37d9 (Solaris DEV 2.2.15). Existing Identity users, roles, local files and migrations remain; no updater/install/modpack changes or production deployment.

## User authentication (HTTPS only outside explicit Development loopback tests)

Existing API paths remain: POST /api/v1/accounts {nickname,email,password,confirmPassword}; POST /api/v1/identity/login {email,password,twoFactorCode?}; POST /api/v1/identity/refresh {refreshToken}; POST /api/v1/identity/logout {refreshToken?} (authenticate bearer); POST /api/v1/identity/forgotPassword {email}; POST /api/v1/identity/resetPassword {email,resetCode,newPassword}; GET /api/v1/identity/confirmEmail?userId=&code=; POST /api/v1/identity/resendConfirmationEmail {email}.
Login/refresh response: {tokenType:"Bearer",accessToken,refreshToken,expiresIn,sessionId}. Persist only token hashes, revocable per-device server sessions, single-use refresh rotation with replay revocation, expiry and security stamp checks. Require confirmed email and reject banned users. Use existing ASP.NET Identity hashes/mail/2FA, not a parallel accounts database.
GET /api/v1/me: {id,nickname,email,createdUtc,lastActiveUtc,emailConfirmed,isAdmin,type:"solaris-id"}; PATCH /api/v1/me {nickname}. Stable ID never changes. Owner routes /api/v1/me/skin GET/PUT PNG, /api/v1/me/playtime GET {vanillaSeconds,moddedSeconds,totalSeconds,source:"trusted-servers"}. Client POST playtime is forbidden; existing legacy history remains local/untrusted, never increments trusted totals. Preserve old DB rows; new trusted tables are separate. Legacy import may retain only an untrusted record, never elevate it into trusted totals.
MFA owner APIs: POST /api/v1/me/mfa/setup {password} => {sharedKey,authenticatorUri}; POST /api/v1/me/mfa/enable {code} => recoveryCodes; optional disable needs password+OTP. Admin session must have real verified OTP amr=mfa. Control policy role SolarisAdmin + amr=mfa; admin roles granted/revoked through audited MFA-protected route. Do not grant first admin by nickname; use explicit out-of-band owner ID bootstrap tooling.

## Secure Minecraft transport without client mods

Unmodified vanilla cannot return a custom launcher credential; Forge login channel also requires a matching client component. Implement an explicit out-of-band connection approval via the existing launcher over HTTPS, with quarantine until success. No nickname/IP/offline UUID counts as proof. No ticket in Minecraft packets, process args or logs. Full automatic client handshake remains a future client component; do not claim it exists.

Server credentials configured as SOLARIS_GAME_SERVERS JSON: [{id:"vanilla-local",mode:"vanilla",key:"<random secret>"},{id:"modded-local",mode:"modded",key:"<random secret>"}]. Server-only requests use Authorization: SolarisServer <key> plus X-Solaris-Server: <id>. Restrict every server credential to its own audience. Launcher configured server IDs (not network addresses) in opt-in settings; no working host/version/config changes.

1. Authenticated launcher POST /api/v1/me/game-tickets {serverId} => {ticket,expiresUtc,serverId}. Short lived single-use random pass, stored hash, user ID/current nickname/device session/audience bound.
2. Quarantined Minecraft connection: trusted bridge POST /api/v1/server/connections {connectionId,nickname} => {code,expiresUtc}. connectionId UUID generated by bridge per actual join; code random human-readable, rate limited, expires. No security decision from Minecraft offline UUID. No key/pass goes into game chat.
3. Player reads code displayed by server and approves in launcher: POST /api/v1/me/game-tickets/approve {ticket,code}. API matches current account nickname + audience + pending connection and atomically consumes ticket. Response {status:"approved"}. Ticket cannot authorize a connection for a different nickname or different server. Code is a locator, never an authorization secret by itself.
4. Bridge GET /api/v1/server/connections/{connectionId} => {state:"pending"|"approved"|"denied", userId?,nickname?,gameSessionId?}. Stable Solaris ID returned only to its server credential, bound to this actual connection. Recheck bans/session revocation/expiry, deny after failed identity validation.
5. Trusted gameplay time: POST /api/v1/server/game-sessions/{gameSessionId}/heartbeat {sequence}; POST .../close {sequence}. API uses its own elapsed clock with capped heartbeat gap, monotonic sequence, no client seconds. Periodic heartbeat ~15 sec, stale cutoff ~45 sec. Idempotent repeats never double count. Only approved live connections count, each gameSession bound server/user/device session. Disconnect closes once. Quarantine seconds do not count. Server polls/heartbeat denial kicks revoked/banned users.

## Java bridges

Paper1.20.1 plugin and Forge1.20.1/47.4.20 SERVER mod, separate modules under bridges/. HTTPS API, Java17. Non-blocking network, main-thread state changes, fail closed, timeout/kick, bounded retries/connections. Until authenticated block movement, commands (except quit), chat, inventory, damage, interactions, pickups, projectile/vehicle actions and protected gameplay. Send only random code instructions to player; redact tokens/key/payloads from logs. Disconnect cancels connection/poll/heartbeat; server shutdown cleans up.
Offline-mode transport UUID remains Minecraft transport metadata; plugin API exposes persistent Solaris userId for ecosystem integrations. No promise of automatic skin rendering or Minecraft inventory UUID migration without a dedicated integration. Test network-independent core and both adapter compilation; true Paper/Forge game-client E2E must be reported separately.
