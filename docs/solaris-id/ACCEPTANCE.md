# Ручная приёмка Solaris ID перед контролируемым развёртыванием

Этот документ — **план незавершённой ручной приёмки**, не отчёт о прохождении.
Автоматические API/Java/HTTP-тесты, Windows compile/publish и наличие JAR не
заменяют Windows GUI/DPAPI и реальный Minecraft client-server E2E. Статус каждой
строки ниже до заполнения владельцем: **НЕ ВЫПОЛНЕНО**.

## Стенд и фиксация результатов

- Отдельный тестовый API, PostgreSQL и почтовые адреса владельца; HTTPS с цепочкой,
  доверенной Windows и Java17. Не использовать live базу, мир или аккаунты игроков.
- Две тестовые Windows-учётные записи/ПК для DPAPI и синхронизации. Перед проверкой
  сохранить исходные локальные данные и запускать отдельную копию лаунчера.
  Не удалять `%APPDATA%/Solaris` и не заменять установленный EXE. Если используются
  данные существующего профиля, резервировать их до теста и менять только тестовую
  учётную запись. DEV/Stable могут иметь разные state directories.
- Записать SHA Git-коммита и SHA-256 каждого EXE/JAR, версии .NET/Java,
  Windows, Paper build, Forge и состав тестовых plugins/mods. Проверка проводится
  на тех же бинарниках/конфигурации, которые предлагаются к приёмке.
- Использовать [изолированные серверные шаблоны](../../bridges/examples/README.md).
  Minecraft EULA не принимается автоматически. Публичный offline-mode стенд запрещён.
- В evidence сохранять идентификатор сценария, время, версию, ожидаемое/фактическое
  поведение и PASS/FAIL. Пароли, токены, server keys, письма/URL с кодами, QR/секреты
  TOTP и расшифрованный `cloud-session.dat` не сохранять и не прикладывать.

## Windows Launcher

| ID | Действие | Ожидаемый результат / блокирующий дефект |
| --- | --- | --- |
| W01 | Открыть отдельную копию без `solaris-id.json`; затем с корректным тестовым HTTPS origin | Без конфигурации понятное сообщение и рабочий локальный вход; после настройки показан точный origin до ввода пароля. Example-домен не считается сервисом. |
| W02 | В новом тестовом аккаунте пройти регистрацию, почту, подтверждение, вход; повторить занятый ник/email и неверный пароль | Регистрация бесплатна, дубликаты отклонены, до подтверждения вход закрыт; ошибки понятны и не содержат секретов. |
| W03 | Войти с «Запомнить меня», полностью закрыть процесс и перезапустить под той же Windows-учётной записью | Сессия восстанавливается без пароля; профиль/скин правильного пользователя. `cloud-session.dat` не содержит открытых credentials. Не расшифровывать его для evidence. |
| W04 | Дождаться штатного истечения access token (15 минут), одновременно открыть профиль/устройства/статистику; перезапустить | Refresh проходит однократно, новое состояние сохраняется; отсутствуют циклы входа, взаимный logout и ложное «подключён» после отказа. Не менять время production-сервера. |
| W05 | Передать только тестовый DPAPI-файл другой Windows-учётной записи/ПК, не перенося Windows credentials | Сессия не восстанавливается, пароль/refresh не раскрываются; требуется обычный вход. Удалить только специально созданную тестовую копию. |
| W06 | Войти с другого ПК тем же Solaris ID, изменить скин; обновить профиль первого ПК | Один постоянный user ID, актуальный скин/профиль, независимые device sessions; локальные часы не прибавляются к доверенным серверным. |
| W07 | Отозвать сессию первого ПК со второго; выполнить запрос на первом и перезапустить | Доступ API закрывается, требуется повторный вход; сохранённая сессия не обходит отзыв. |
| W08 | Выполнить logout онлайн, закрыть/открыть лаунчер; повторить logout при отключённом тестовом API | Онлайн-сессия отозвана; локальный файл удалён. При offline logout показано, что удалённый отзыв не подтверждён, и дано действие с другого устройства после восстановления сети. |
| W09 | Отключить только тестовый API перед восстановлением сессии, затем вернуть связь | Отображается offline-состояние; локальная игра допустима, защищённый Minecraft требует API и подтверждения; нет зависшего UI или выдуманного успешного отзыва. |
| W10 | Проверить недоверенный/истёкший сертификат и HTTPS redirect на отдельном тестовом origin; затем сменить origin рядом с EXE | TLS/redirect не обходятся, старые credentials не уходят на новый origin, нет автоматического доверия сертификату. |
| W11 | Начать медленное обновление профиля, выйти/сменить аккаунт до ответа | Поздний HTTP/UI callback не возвращает старый профиль, скин, устройства или токены. |
| W12 | Включить TOTP, сохранить recovery-коды владельцем, войти OTP; отдельно войти одним recovery-кодом | После enable требуется повторный вход. Recovery-код одноразовый; owner-профиль доступен, Control recovery-only сессии закрыт. TOTP secret очищается при выходе. |
| W13 | Войти старым локальным аккаунтом, проверить настройки/скин/новости; попытаться зарегистрировать иной локальный аккаунт поверх него | Старые данные сохранены, файл аккаунта не перезаписан; перенос скина требует подтверждения старого пароля, исходник остаётся. |
| W14 | На тестовом установленном клиенте проверить существующие Vanilla 26.2 / Java25 и Modded 1.20.1 / Forge47.4.20: запуск, отмену загрузки, проверку файлов | Прежние директории/версии/модпак не меняются из-за Solaris ID; нет регрессии обработчиков. Не применять реальный DEV/Stable update к установленному лаунчеру в рамках этого теста. |
| W15 | При настроенном Vanilla audience запустить отдельный добровольный клиент 1.20.1 / Java17 | Он размещён в отдельном `solaris-id-clients/vanilla-1.20.1`, не подменяет 26.2; отмена/повторный запуск корректны. Именно этот клиент совместим с Paper1.20.1. |
| W16 | При работающем клиенте открыть лаунчер через Alt+Tab, выполнить подтверждение своего игрового кода | Лаунчер доступен; пароль/пропуск не вводятся в Minecraft chat, код и сервер явно подтверждаются. Старое поведение окна без audience сохраняется. |

Автоматический файл-контроль `check_preserved_systems.py` подтверждает неизменность
известных updater/install файлов, но не заменяет W14. Само обновление игрокам не
публикуется. Проверка отказа записи DPAPI/диска допускается только на отдельном
тестовом профиле: ожидается сообщение о невозможности запомнить вход и отсутствие
устаревшего refresh-файла, без выдачи приложению дополнительных прав.

При потере heartbeat учитывается только разрешённый ограниченный промежуток. |
| M12 | Остановить bridge/сервер и перезапустить | Нет сохранённой временной invulnerability/creative/no-gravity привилегии; все новые соединения снова требуют подтверждения, lifecycle cleanup не освобождает карантин. |

| M14 | Попытка войти с чужим ником одновременно с владельцем, наблюдение pre-auth playerdata/пакетов | Записать ограничения offline-mode: возможны duplicate-nickname DoS и передача данных до join gate. Не объявлять транспорт конфиденциальным/защищённым от активного in-path атакующего. Публичный выпуск блокирован до принятого владельцем решения о защищённом игровом транспорте. |

Стабильный Solaris UUID надо проверять через серверную интеграцию, вызывающую
существующий `solarisId(...)`, и owner `/api/v1/me`, без вывода токенов. Совпадение
ника, показанного скина или offline UUID недостаточно. Если нет доверенного
диагностического consumer для этого hook, M04/M10 отмечаются **НЕ ВЫПОЛНЕНО**;
не подменять результат предположением. Автоматический Java HTTP probe проверяет
backend UUID, но не вызов hook внутри настоящего игрового сервера.

## Решение владельца о выпуске

Перед разрешением обновления должны быть зафиксированы:

1. Домен, TLS, PostgreSQL runtime/migration роли, SMTP/DNS и реальная внешняя
   доставка писем; секреты находятся вне репозитория/сборки, backup/restore
   проверен, выбран согласованный recovery point API/БД/ключей.
2. Все W/M-сценарии либо PASS на точных бинарниках, либо явно принятые владельцем
   ограничения. Критические FAIL по личности, quarantine, replay, session revoke,
   утечке secrets, данным пользователей или запуску клиентов не допускаются.
3. Для offline-mode явно решены границы транспорта, pre-auth playerdata и доступ
   из недоверенной сети. Текущие мосты не создают зашифрованный Minecraft transport
   и не гарантируют полную изоляцию произвольного стороннего серверного кода.
4. Скины внутри Minecraft, inventory/advancement по постоянному Solaris UUID и
   полностью автоматический login handshake отдельно определены как незавершённые.
   Ручной code approval должен быть описан пользователю без обещания бесшовного входа.
5. SHA-256/версии утверждены, план остановки/отката готов. Публикация Launcher,
   установка bridge на рабочие серверы и миграция production требуют **отдельного
   явного разрешения**; выполнение этой инструкции такого разрешения не заменяет.

Пустая таблица, успешная компиляция или зелёный GitHub CI не означают выполненную
ручную приёмку. Известные дефекты и незавершённые проверки передаются владельцу
вместе с решением GO / NO-GO; по умолчанию до приёмки **NO-GO для публичного выпуска**.
