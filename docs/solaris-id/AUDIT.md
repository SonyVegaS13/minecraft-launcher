# Solaris ID — этап A: аудит

База: `solaris-2.2-dev`, `efb37d9596b4c73b9d24a38372035225658e6f5b` (2.2.15). Рабочая ветка: `feature/solaris-id`.

До начала изменений в другой экспериментальной ветке находилась незакоммиченная правка `tests/PlanetaryWpf.Tests/Program.cs`. Она сохранена в Git stash `Preserve pre-Solaris-ID planetary WPF test work` и отдельном binary patch вне checkout. В Solaris ID она не включается. Исходники SMART MONKEYS не используются и не меняются.

| Область | Уже существовало | Что требуется доработать |
|---|---|---|
| Аккаунты | ASP.NET Core8, PostgreSQL, Identity, EF миграции, уникальный ник, email-подтверждение/сброс через SMTP | DB-уникальность email, валидация null/гонок, редактирование профиля, последняя активность |
| Сессии | Identity bearer login/refresh, глобальная security stamp | Серверный реестр отдельных устройств, logout/revoke, одноразовая ротация refresh и защита от повторного использования |
| Windows-клиент | Реальный HTTP-клиент, DPAPI CurrentUser, профили по ID | Синхронизированный refresh во время работы, отзыв при выходе, ввод/настройка MFA, безопасная конфигурация API |
| Скин | PUT/GET PNG, локальный кэш и превью | Ограничение потокового тела, полная валидация PNG, обновление уже существующего кэша с другого ПК |
| История | Локальные часы, загрузка клиентских сеансов и legacy-импорт | Нельзя считать эти значения доверенной серверной статистикой; сохранить отдельно, новые часы получать только от серверов |
| Minecraft | Vanilla26.2/Java25 и Modded1.20.1/Forge47.4.20; offline launch session | Ни одна offline session не доказывает Solaris ID. Нет одноразовых пропусков или серверных Auth Bridge |
| Solaris Control | Поиск, бан/разбан, глобальный отзыв, письмо сброса, журнал; роль + MFA-policy | Проверенный MFA flow, управление ролями, статистика/status, проверка результатов административных операций |
| Проверки | CI build/migrations/health + запрет анонимного Control | Реальные HTTPS/PostgreSQL/SMTP security/integration-сценарии, Java bridges, регрессия запуска/автообновления |

Встроенные Identity refresh обычно проверяют security stamp, а OTP-вход способен выдавать `amr=mfa`. Их нельзя объявлять неработающими без E2E-проверки; выявлен именно недостаток жизненного цикла отдельных серверных сессий.

Подтверждённые дефекты: клиентская подделка часов; переполнение суммы legacy-часов; некоторые null/некорректные JSON вызывают500; регистрационная гонка email; skin stream без Content-Length может неограниченно выделять память; PNG проверяется только по заголовку; cloud-скин скачивается только при отсутствии файла; local register способен заменить предыдущую запись другим ником; logout не отзывает отдельное устройство на сервере.

## Ограничения игровых протоколов

Vanilla1.20.1 отвечает «канал не понят» на неизвестный Login Plugin Request. Forge SimpleChannel требует соответствующий клиентский мод. Полностью автоматический собственный login без дополнительного компонента отсутствует; проверка ника/IP/offline UUID его не заменяет.

Для совместимости без модификации существующего модпака выбран явный out-of-band flow: краткоживущий пропуск остаётся в памяти лаунчера, сервер создаёт код отдельного подключения, пользователь подтверждает его в лаунчере по HTTPS, API атомарно связывает пропуск с сервером/аккаунтом/сессией/подключением. До успеха игрок в карантине. Игра не получает bearer-секрет. Автоматический транспорт остаётся отдельной будущей клиентской интеграцией.

Указанный в ТЗ Vanilla1.20.1 несовместим с имеющейся Vanilla26.2. Добавление отдельного opt-in профиля1.20.1 необходимо для проверки целевого сервера, но существующие Vanilla26.2, Modded-пакет, серверные адреса и автообновление не заменяются.

## Проверки и внешние зависимости

Среда: Linux, .NET SDK8.0.426 уже сохранён, WPF можно скомпилировать с EnableWindowsTargeting; Windows GUI недоступен. Для локальной проверки подготовлены отдельная PostgreSQL16, SMTP STARTTLS/AUTH sink и собственный тестовый TLS CA. Они не являются production-хостингом или настоящей доставкой почты пользователям.

Для развёртывания потребуются отдельный хост Solaris ID, PostgreSQL/backup, домен/TLS, SMTP и доступ оператора к Paper/Forge для установки мостов и назначения отдельных серверных ключей. Эти доступы не требуются для доступной локальной реализации. Рабочие серверы, пользовательские релизы и автообновление не разворачиваются автоматически.
