SOLARIS LAUNCHER — SOLARIS ID — TEST BUILD

Эта отдельная тестовая версия не устанавливает и не обновляет рабочий Solaris.
Это настоящий WPF-лаунчер, а не демонстрационное окно или фиктивная авторизация.

ЗАПУСК
1. В GitHub Actions artifact находится готовый Solaris-Launcher-ID-TEST-win-x64.zip.
   Извлеките этот ZIP, затем распакуйте его целиком в новую доступную для записи
   папку, например в отдельную папку на Рабочем столе. Не распаковывайте поверх
   установленного Solaris, его клиента, Program Files или рабочего профиля.
2. Запустите SolarisLauncher.exe. Права администратора и установленный .NET Runtime
   не нужны. Не перемещайте EXE отдельно от приложенных native DLL.
3. Убедитесь, что окно помечено TEST BUILD. BUILD-INFO.txt содержит исходный commit,
   состав и SHA-256 бинарников; TEST-VERIFICATION.json — результат runner smoke.

ИЗОЛЯЦИЯ
Настройки, локальный аккаунт, сессия Solaris ID, скины, логи и игровые клиенты
тестовой версии находятся в test-data рядом с EXE. Рабочие профили Solaris,
клиенты и модпак не переносятся и не перезаписываются. Production-автообновление,
самоустановка и автоматическое подключение к рабочим серверам в этой сборке
отключены. Не копируйте в неё чужие cloud-session.dat или рабочие каталоги.

SOLARIS ID API
Готовый внешний тестовый API сейчас не включён в архив. Ни fake API, ни пароли,
server keys, сертификатные private keys или токены не поставляются.

Для настоящей проверки регистрации/входа оператор должен подготовить отдельный
Solaris ID API с PostgreSQL, доверенным HTTPS и работающим SMTP.
1. Скопируйте config/solaris-id.example.json в config/solaris-id.test.json.
2. Укажите ApiOrigin вида https://ВАШ-ТЕСТОВЫЙ-ДОМЕН/ (только HTTPS origin, без
   login/password, query, fragment или дополнительных путей).
3. Для серверной проверки укажите отдельные audience VanillaServerId и
   ModdedServerId тестовых серверов. Это открытые ID; секреты мостов сюда не пишутся.
4. Перезапустите тестовый EXE и проверьте показанный адрес перед вводом пароля.
   Не отключайте TLS/hostname verification и не используйте production-аккаунт
   для непроверенного API. Обычная сессия сохранена Windows DPAPI CurrentUser.

ПРОВЕРКА УЧЁТНОЙ ЗАПИСИ
Выберите Solaris ID, зарегистрируйте уникальные nickname/email и пароль,
подтвердите email по письму своего API, затем войдите. При включённом
«Запомнить меня» закройте EXE и откройте снова: действующая сессия должна
восстановиться. Проверьте профиль/скин, выход, истечение/отзыв сессии, недоступный
API и MFA, если MFA настроена. Регистрация и вход используют настоящий backend;
без него online-проверки выполнить нельзя.

БЕЗ API
Доступны запуск интерфейса, настройки и отдельная локальная регистрация/вход.
Локальный аккаунт не является доказательством авторизации на Minecraft-сервере.
Облачные регистрация, email, профиль/скин, восстановление и MFA требуют API/SMTP.
Игровые файлы не входят в этот ZIP. Клиенты устанавливаются отдельно в test-data;
проверка реального Minecraft, Forge/модпака и авторизации требует отдельного стенда.
Автоматического подключения к рабочим игровым серверам нет. Тестовый сервер
добавляется вручную и не должен использовать production credentials.

СТАТУС ПРОВЕРКИ
Windows runner проверяет запуск процесса, создание и отрисовку WPF-окна и
штатный выход дважды. Дополнительно проверяется Windows DPAPI CurrentUser на
случайном тестовом значении между двумя процессами; это не настоящая API-сессия.
Это не ручной визуальный осмотр на RX 580 и не проверка настоящего
Solaris ID API или игрового клиента. Подробности/commit находятся в BUILD-INFO.txt.

УДАЛЕНИЕ
Закройте тестовый лаунчер и его тестовые игровые процессы. Удалите только новую
распакованную папку вместе с test-data. Не удаляйте %APPDATA%\Solaris, рабочие
папки Solaris Launcher и Minecraft. Если была создана настоящая cloud-сессия,
сначала выйдите с доступным API или отзовите тестовое устройство в своём профиле.
