# Solaris ID — клиент лаунчера

## Подключение после развёртывания

Оператор размещает **несекретный** `solaris-id.json` рядом с установленным EXE. Пример — `solaris-id.example.json`; указанный домен является примером и не предоставляет API. Нужен настоящий HTTPS origin без пути, query, fragment или userinfo, с доверенным Windows сертификатом. `VanillaServerId` / `ModdedServerId` должны точно совпадать с audience соответствующего серверного моста. Это идентификаторы, не IP-адреса. Серверные ключи никогда не помещаются в этот файл или в лаунчер.

`OfficialApiOrigin` остаётся пустым до подтверждённого развёртывания. В обычной сборке произвольный environment override не используется. Для DEV разрешён `SOLARIS_ID_API_ORIGIN` с той же HTTPS-проверкой. На экране входа виден origin, которому передаются учётные данные; сохранённая сессия используется только для точно совпавшего origin. До ввода пароля следует проверить адрес. Нельзя отключать TLS-проверку или автоматически доверять самоподписанному сертификату.

## Сессия и профиль

Существующий экран Solaris ID используется для регистрации, входа, подтверждения/восстановления email и повторного ввода пароля. Добавлены OTP и явный выбор резервного кода. Секрет сессии хранится DPAPI CurrentUser только при «Запомнить меня»; обновления сериализованы на одну device session, refresh одноразовый. Logout обращается к серверу, затем удаляет локальную сессию; при отсутствии сети честно сообщает, что удалённый отзыв не подтверждён. Устройства можно просмотреть и отозвать отдельно.

Профиль отображает постоянный ID, ник, email владельца, дату регистрации, активность, сетевое состояние, скин и подтверждённые серверные часы. Можно изменить ник (сервер отзывает сессии — требуется новый вход), настроить приложение 2FA и получить резервные коды. Ключ 2FA/резервные коды показываются только в памяти текущего окна, не пишутся в файл и очищаются при выходе. После включения 2FA текущая сессия уже отозвана; нужно сохранить коды и войти снова.

Скины обновляются с API и при наличии кеша. Solaris ID не подменяет отсутствующий скин ответом стороннего сервиса по совпавшему нику. Ограничены размер 512 КиБ и PNG 64×64; размеры проверяются до декодирования. Игровое отображение скина другим участникам Minecraft требует отдельной совместимой интеграции сервера/клиента; WPF-предпросмотр её не имитирует.

## Локальные данные

Старые аккаунты, настройки и activity.json сохраняются. Регистрация другого локального аккаунта больше не перезаписывает существующий файл. Перенос подтверждённого старым локальным паролем скина не удаляет исходник; заменяемый облачный кеш скина получает резервную копию. Старые часы/очереди сохраняются как **локальная история**, не отправляются как доверенные часы и не прибавляются к серверным итогам. Старые кешированные cloud totals не считаются доверенными до ответа нового API с `source: trusted-servers`. Записи локального процесса и обновления серверных итогов сериализованы и сохраняют данные друг друга.

## Подключение Minecraft

Мост не считает offline UUID или ник доказательством владения Solaris ID. Без разрешения API игрок находится в серверном карантине. С существующим клиентом Minecraft необходим ручной безопасный шаг:

1. Войти в Solaris ID, запустить клиент и подключиться к нужному защищённому серверу.
2. Сервер покажет код текущего подключения. В профиле лаунчера выбрать Vanilla/Modded, ввести **свой** код и подтвердить аккаунт/сервер/код в диалоге.
3. Лаунчер по HTTPS получает короткоживущий одноразовый пропуск и подтверждает это подключение. Мост независимо проверяет разрешение и снимает карантин.

При настроенном audience лаунчер готовит пропуск перед запуском и сохраняет его только в памяти с TTL; просроченный пропуск получает заново. Пропуск не отображается, не записывается в файл, лог, переменные окружения или командную строку Minecraft. При отказе запроса повторное использование не происходит: локальная ссылка удаляется. Одного кода недостаточно для авторизации, и нельзя подтверждать коды, полученные от других людей. Полностью автоматического handshake без клиентского компонента здесь нет.

Для этого сценария лаунчер остаётся доступен через Alt+Tab, пока игра работает. Обычный запуск без audience сохраняет прежнее скрытие окна. При отсутствии API локальная игра остаётся доступна, защищённый сервер доступа не получает.

## Версии Vanilla

Существующий Solaris Vanilla DEV использует **26.2 / Java 25**. Его версия, game directory, обновление, проверка и обработчики запуска сохранены. С Paper 1.20.1 этот клиент несовместим.

В профиле добавлен **отдельный добровольный клиент 1.20.1 / Java 17**. Он использует `%APPDATA%/Solaris/.../solaris-id-clients/vanilla-1.20.1`, существующие CmlLib/Java/прогресс/отмену и локальный BuildInstalledMinecraftProcessAsync. Не подменяет существующий Vanilla и не меняет Modded/Forge/модпак. Адрес сервера пользователь добавляет вручную; новые адреса не придумываются. Чтобы использовать кнопку, оператор должен настроить Vanilla audience, пользователь должен войти в ID. Скачивание/запуск Minecraft в Linux не выполнялись.

## Проверки

Кросс-платформенный протокол: `dotnet run --project tests/SolarisIdClient.Tests -c Release`. Тесты используют scripted HTTP и не являются подтверждением живого backend или Minecraft. WPF Release собирается на Linux с `-p:EnableWindowsTargeting=true`. Нативные UI/DPAPI, оба клиента Minecraft, импорт/освещение скина и поведение окна во время карантина требуют ручной Windows-проверки. Сборка не публиковалась игрокам, установленный лаунчер и рабочие серверы не менялись.
