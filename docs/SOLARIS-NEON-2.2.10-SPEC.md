# SOLARIS NEON 2.2.10 — техническое задание
**Статус:** все 10 продуктовых пунктов согласованы. Это описание требований, а не утверждение о завершённой реализации.
**Исходный стабильный релиз:** Neon 2.2.9.
**Ветка разработки:** `solaris-2.2-dev`.
**Целевая платформа:** Windows x64, WPF, .NET 8, однофайловая самодостаточная сборка.
**Дата фиксации требований:** 10 октября 2026 г.

> **Правило выпуска:** не публиковать `neon-v2.2.10` и не заменять рабочую 2.2.9 до успешной сборки, ручных проверок игрового запуска и проверки безопасного обновления. Не считать «код добавлен» равнозначным «функция испытана».

## Принципы
- Сохранять уже работающие элементы 2.2.9: Solaris Vanilla/Modded, утверждённые изображения двух карточек, тяжёлое размытие в покое и резкое изображение при наведении, существующую загрузку Minecraft и Forge, пользовательские файлы.
- Не переписывать исправные подсистемы с нуля без необходимости.
- Пользовательские миры, моды, игровые настройки, Java и аккаунты находятся отдельно от устанавливаемого SolarisLauncher.exe и не удаляются при обновлении.
- Всё штатное взаимодействие, кроме служебного окна помощника обновления, происходит внутри одного окна Solaris.
- Состояние установки и ошибки объяснять игроку понятным русским текстом; процент показывать только из реального измерения, неизвестную продолжительность — анимацией без ложного числа.

## 1. Умная установка Minecraft, Java и компонентов
**Карточка Solaris Vanilla:** целевая версия Minecraft `26.2`, целевая Java `25`, библиотеки и ассеты.
**Карточка Solaris Modded:** Minecraft `1.20.1`, Forge `47.4.20`, Java `17`, клиентская модовая сборка.

Алгоритм после нажатия «Играть»:
1. Определить выбранную карточку и её профиль требований; не смешивать папки и конфигурации Vanilla/Modded.
2. Проверить наличие версии Minecraft и относящихся к ней манифестов, библиотек, natives, ассетов, Java нужного major-version и (для Modded) Forge и модов.
3. Если компонента нет — сообщить «Minecraft … отсутствует — устанавливаем», «Java … отсутствует — скачиваем» или аналогичный статус.
4. Если компонент на месте и валиден — «Minecraft установлен», «Java … найдена». Не скачивать повторно.
5. При повреждении файла сверить размер/контрольную сумму с доверенным манифестом и восстановить **только отсутствующее или повреждённое**, сохраняя остальные корректные файлы и пользовательские миры.
6. При следующем запуске (хоть завтра) повторить быструю проверку; если всё в порядке, показать «Все компоненты готовы. Запускаем Minecraft…» и запустить без повторной загрузки.
7. При обрыве связи, отмене или закрытии программы сохранять корректно скачанное, не оставлять частично распакованный архив за «готовый» компонент; обеспечивать безопасную повторную попытку.
8. При подборе Java проверять не только существование `java.exe`, но и major-version; не запускать Modded на 25 и Vanilla на 17 из-за первого найденного пути. Учитывать совместимость реального манифеста выбранной версии игры.
9. Для библиотек Minecraft допустимо использовать проверенный `CmlLib.Core` и его установщик Java/зависимостей; запрещено молча скачивать произвольные JDK из непроверенных источников.

**Критерии приёмки:** чистый ПК, только Vanilla, только Modded, обе игры, вторичный запуск офлайн после установленной игры, удалённая библиотека, повреждённый jar, отсутствующая Java, две установленные Java, остановка скачивания и повтор.

## 2. Единая панель загрузки
Единый **SOLARIS IGNITION** располагается в основной области под карточками. Вместо дублирующих статусов отображает единственную текущую фазу:
- проверка, Java, Minecraft, ассеты/библиотеки, Forge/моды, запуск;
- отображение фактического прогресса, если размер/количество известно; иначе неопределённый индикатор без фиктивных 25/45/85%;
- запуск, отмена и повтор после исправимой ошибки в том же интерфейсе;
- итог «Готово» / «Запускаем» / понятное сообщение об ошибке.
Разрешается использовать общий диапазон 0–100 только при документированной весовой модели реально измеренных этапов.

## 3. RAM в «Настройках»
Убрать единственный общий ползунок из главного экрана. По кнопке **⚙ Настройки** открывается внутренняя страница с отдельными ползунками Vanilla и Modded, размер — в МБ/ГБ. Границы рассчитываются исходя из **физической RAM** на компьютере. Не выдавать игре всю RAM: оставлять запас Windows и другим приложениям. Показывать предупреждение, если для модов доступно мало. Настройки постоянны между перезапусками и обновлениями и применяются именно к выбранному игровому профилю. Сохранение — атомарное; повреждённый конфиг не блокирует вход.

**Тесты:** 4/8/16/32 ГБ, раздельные значения, перезапуск Solaris, обновление Solaris, запуск обоих режимов, недостаток RAM.

## 4. SOLARIS PLAYER PROFILE
Клик по аватару или кнопке профиля открывает страницу в том же окне.
Обязательные элементы:
- никнейм, тип аккаунта (локальный или Solaris ID) и понятный реальный статус;
- дата регистрации, если действительно записана при создании. Для ранее созданных аккаунтов — «Неизвестна», а не выдуманная дата;
- статистика Vanilla, Modded, суммарное время и активность;
- 2D-предпросмотр Minecraft-скина, переключатель в **вращаемый мышью 3D-предпросмотр**, импорт собственного PNG-скина (контроль размера и формата), стандартный Steve при отсутствии;
- управление профилем/выход, для Solaris ID — безопасный сценарий смены пароля.
Скин, ник и аккаунт остаются непротиворечивыми при смене пользователя. Не менять исходные игровые скины/файлы по умолчанию без согласия.

## 5. SOLARIS ACTIVITY вместо достижений
С главного экрана **удалить достижения**, не заменяя их фальшивыми «уровнями». Добавить SOLARIS ACTIVITY:
- последняя сыгранная карточка;
- продолжительность последнего завершённого сеанса;
- дата/время последнего запуска;
- переход к полной странице профиля.
Пустое состояние: «Вы ещё не играли». Информация отдельная по аккаунту и не подменяется общей статистикой компьютера.

## 6. Наигранное время
Отслеживать реальный **процесс Minecraft** от успешного запуска до завершения, а не открытое время Solaris. Считать одиночные и многопользовательские сеансы. Сохранять раздельные секунды Vanilla/Modded, общую сумму, последний режим, продолжительность последнего сеанса и время старта. Периодически сохранять прогресс, переживать штатное завершение и минимизировать потери при аварийном закрытии. Не удваивать секунды из-за повторной записи. Старые сессии, которые не измерялись, не выдумывать. В будущем — синхронизация с Solaris ID с идентификаторами сессий и защитой от двойного начисления на разных ПК.

**Тесты:** короткая игра, игра 60+ минут, Alt+F4 Minecraft, одновременный лаунчер, одиночный мир, сервер, отключение питания, перезапуск, два разных аккаунта.

## 7. SOLARIS ID + инфраструктура Millida
**Согласовано:** сервис авторизации и Minecraft-сервер должны размещаться у **Millida**, но как независимые сервисы, чтобы перезапуск Minecraft-сервера не ломал регистрацию и авторизацию. Реальная поддержка ASP.NET Core, PostgreSQL, HTTPS/TLS, домена и/или VPS должна быть подтверждена **до развёртывания**; сам факт выбора хостера не подтверждает его возможности.

Предпочтительная архитектура:
- отдельный ASP.NET Core Web API и PostgreSQL, на сервере использование ASP.NET Identity; подтверждение email, лимиты частоты запросов и блокировка перебора;
- регистрация (уникальный ник, email, пароль), авторизация, восстановление пароля через одноразовые ограниченные по времени токены, завершение/отзыв сессий;
- пароль не хранится в открытом виде, только стойкий соль-ориентированный хэш; передача только по HTTPS;
- клиент хранит refresh/access tokens защищённо средствами Windows, не выводит их в журналы, не записывает пароль в настройки;
- подтверждённая миграция **старого локального аккаунта** через проверку старого пароля/владения email, без захвата чужих никнеймов и потери игровых данных;
- игрок может входить на другом ПК и получать подтверждённые облачные профиль/скин/статистику; локально кэшируются только необходимые данные и заранее авторизованному игроку предлагается ограниченный офлайн-режим;
- SOLARIS CONTROL: отдельная защищённая панель администратора с обязательной 2FA, списком и поиском пользователей, блокировкой/разблокировкой, отзывом сессий, запуском сброса пароля и аудитом изменений. Даже админ **не видит исходные пароли**.
- обеспечить резервное копирование базы, миграции схемы, мониторинг работоспособности и секреты на сервере, не в GitHub.

**Важная граница:** Solaris ID НЕ тождественен платной лицензии Microsoft/Minecraft; серверная политика допуска офлайн-игроков — отдельный вопрос конфигурации сервера.

**Критерии приёмки:** регистрация, подтверждение email, вход на другом ПК, неверный пароль и лимит попыток, отзыв токена, потеря связи, восстановление, конфликт ника, миграция локального аккаунта, восстановление БД, 2FA админа и аудит действий.

## 8. Фирменное солнышко-глаз Solaris
Вместо стандартной кнопки использовать **жёлтый логотип Solaris в образе закрытого/открытого глаза**. Справа внутри каждого поля пароля, анимированный плавный переход примерно за 160–220 мс.
- закрытый глаз: пароль скрыт (по умолчанию);
- открытый глаз: пароль виден;
- повторный клик возвращает скрытие; клавиатура и мышь равноправны;
- независимо для «Пароль» и «Повторите пароль» при регистрации, также на входе;
- при переходе/выходе пароль снова скрывается, значение не стирается при простом показе;
- предупреждение Caps Lock без лишних модальных диалогов;
- отображение plaintext возможно только на экране по действию игрока; пароль не копируется в логи или постоянное хранилище.

## 9. SOLARIS SAFE UPDATE
**Цель:** избавиться от нескольких окон, повторных запросов, циклов перезапуска и ошибочных повторных обновлений, которые наблюдались при переходе на 2.2.9.

Порядок: проверка релиза в GitHub → **одно подтверждение** → скачивание нового EXE во временный файл с отображением реального прогресса → проверка SHA-256 и версии → передача одному помощнику → ожидание закрытия прежнего EXE → резервная копия `.previous` → атомарная замена → **один** запуск новой версии → подтверждение инициализации → фиксация успеха.

Защита:
- один процесс установки за счёт межпроцессной блокировки;
- запрещено запускать вторую копию Solaris и повторно показывать согласие в той же попытке;
- при сбое не создавать бесконечный цикл, фиксировать версию/attempt ID/состояние;
- при невозможности старта нового EXE откатить старый EXE из резервной копии;
- при отключении питания предусмотреть восстанавливаемое состояние, отдельные журналы, безопасную ручную или автоматическую диагностику;
- успешный релиз должен иметь EXE, архив и SHA256SUMS.txt, проверенный канал HTTPS/GitHub, в перспективе цифровую подпись Windows;
- пользовательские данные и Minecraft не трогать.

**Тесты:** обновление 2.2.9→2.2.10, два одновременных процесса, отказ записи, повреждённая загрузка, несовпадение SHA, некорректная версия, зависший старый EXE, неудачный запуск нового EXE, откат, отключение питания, переоткрытие после ошибки, отсутствие зацикливания.

## 10. SOLARIS IGNITION — плазма
Утверждён **не обычный скучный progress bar**, а насыщенная горячая жёлто-оранжевая плазменная полоса с движущейся энергией, сияющей продвигающейся кромкой и маленькими золотыми искрами. На достижении **реальных** 100% — короткая праздничная золотая вспышка. Подпись фазы и статус остаются легко читаемыми; анимация должна быть лёгкой для GPU и не включать тяжёлый перекадровый блюр.

## Этапы внедрения
**Этап A — защита работающего лаунчера:** ветка разработки, резервные копии, CI-сборка, тест установщика, защита обновления, тест отката. Старую версию не публиковать поверх.
**Этап B — локальный UX и игровой клиент:** №1, №2, №3, №5, №6, №8, №10; отдельно проверять обе игровые карточки на чистом и уже установленном ПК.
**Этап C — профиль:** №4, 2D/3D-скин, PNG, реальные показатели, отсутствие ложных дат.
**Этап D — облако:** проверить тариф Millida, развернуть API, БД и TLS; затем регистрацию, миграцию, токены, синхронизацию и SOLARIS CONTROL с аудитом.
**Этап E — выпуск:** GitHub CI success, реальный тест запуска Windows, безопасность/восстановление аккаунтов, полностью пройденный тест автообновления, выпуск `neon-v2.2.10` только после подтверждения.

- **Сборка CI** проверяет компиляцию WPF на Windows, но сама по себе не доказывает работоспособность игрового запуска.
