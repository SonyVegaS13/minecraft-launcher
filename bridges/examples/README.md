# Изолированные тестовые Paper/Forge-серверы

Это **шаблоны для новой песочницы**, не конфигурация рабочих Solaris-серверов.
Они не были запущены настоящим Minecraft-клиентом в Cloud. Не копируйте их поверх
существующего сервера, мира, playerdata, plugins/mods или конфигурации модпака.

| Компонент | Paper | Forge |
| --- | --- | --- |
| Minecraft | 1.20.1 | 1.20.1 |
| Сервер | Проверенный Paper 1.20.1, номер build и SHA-256 записать при скачивании | Forge **47.4.20**, официальный installer |
| Java | 17 | 17 |
| Bridge | `solaris-id-paper-1.0.0.jar` в `plugins/` | `solaris-id-forge-1.20.1-0.1.0.jar` в `mods/` |
| Audience | `vanilla-sandbox` / mode `vanilla` | `modded-sandbox` / mode `modded` |
| Игровой порт | `127.0.0.1:25575` | `127.0.0.1:25576` |
| Мир | Новый `solaris-id-sandbox-paper` | Новый `solaris-id-sandbox-forge` |

1. Вне checkout создать **две новые пустые папки**. Получить соответствующие
   серверные дистрибутивы из официальных источников, проверить Java/версию и
   контрольные суммы. Paper build не подменять другой версией Minecraft.
   Forge server installer использовать только в новой папке; сохранить его
   штатные `run.sh`/`run.bat` и argument files. Клиентский модпак не пересобирать.
2. Скопировать только шаблон нужного `server.properties` и `eula.txt` в новую
   папку. В `eula.txt` намеренно стоит **`eula=false`**. До запуска владелец должен
   самостоятельно ознакомиться с официальной Minecraft EULA и принять её,
   если согласен. Автоматического согласия, `EULA=TRUE` или обхода нет.
3. После отдельного решения владельца запустить чистый сервер штатным способом,
   остановить, установить единственный соответствующий server-only bridge.
   Для Forge использовать совместимый тестовый набор серверных модов и уже
   существующий совместимый клиент 1.20.1/47.4.20; не переносить рабочий мир.
4. Настроить отдельный тестовый Solaris ID API с PostgreSQL и доверенным HTTPS.
   `api-game-servers.example.json` задаёт соответствие audience/mode, но пустые
   `key` **намеренно невалидны**. Через secret manager создать два различных
   случайных ключа (не менее 32 символов), заполнить их только на API-хосте и в
   окружении соответствующего сервера. Не записывать ключи в Java CLI, чат,
   `server.properties`, лаунчер, Git или результат теста. Ключи разных audience
   нельзя переиспользовать. На API JSON задаётся в `SOLARIS_GAME_SERVERS`.
5. `bridge.env.example` содержит только HTTPS origin и audience. Секрет
   `SOLARIS_SERVER_KEY` требуется внедрить защищённо в окружение Java-процесса;
   копирование примера само по себе не включает авторизацию. При отсутствии
   корректного ключа bridge обязан отказать в доступе.
6. Для лаунчера рядом с отдельной проверяемой копией EXE разместить
   `launcher.sandbox.example.json` **под именем `solaris-id.json`**, заменив
   example origin на свой тестовый HTTPS origin. Windows/JVM должны доверять
   реальной цепочке сертификата. Не отключать TLS/hostname verification.

Примеры не запускают сервер и ничего не устанавливают. Paper запускается Java17
с выбранным официальным Paper JAR; Forge — его сгенерированным `run.sh`/`run.bat`.
Для ограниченного стенда можно задать `-Xms1G -Xmx2G` через штатный JVM-файл
только тестового сервера; не запускать оба Minecraft-сервера одновременно на
машине с 8 ГБ RAM вместе с тяжёлым клиентом.

## Граница доверия

В примерах `online-mode=false` нужен для проверки существующего Solaris offline
клиента и **не является безопасной авторизацией сам по себе**. Поэтому серверы
слушают только loopback. Для другого ПК использовать контролируемый приватный
канал/туннель; не менять bind на публичный интерфейс ради этой проверки и не
пробрасывать порт в Интернет. `enforce-secure-profile=false` не доказывает
личность: её подтверждает только одобрение конкретного подключения через API.

Не выдавать OP тестируемому обычному игроку. RCON/query/command blocks отключены.
Не устанавливать AuthMe/другие login-плагины как замену тесту Solaris ID. До
одобрения bridge должен удерживать игрока в карантине, а не разрешать игру по нику.

Offline UUID остаётся транспортным ключом. Playerdata/часть игровых пакетов могут
быть загружены или отправлены до join callback. HTTPS-код не шифрует Minecraft
offline transport, не гарантирует конфиденциальность инвентаря до входа, не
устраняет duplicate-nickname DoS и не является песочницей сторонних модов.
Постоянный ID берётся только из `solarisId(Player/ServerPlayer): Optional<UUID>`;
empty означает отсутствие подтверждения. Перенос инвентаря/advancement и скины
в Minecraft требуют отдельной интеграции. Нельзя заявлять полное исключение
подмены личности по результату одной только сборки или API-теста.

Подробная ручная приёмка: [ACCEPTANCE.md](../../docs/solaris-id/ACCEPTANCE.md).
